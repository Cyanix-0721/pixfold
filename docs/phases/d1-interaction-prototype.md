## D1：交互原型

> **✅ 复用关系(2026-09-21 用户确认)**:**D1 的 UI 将作为 D4 MVP 的基座**,
> **不是一次性原型**。即:本仓库 `android/` 的原型代码在 D1 通过后
> **就地演进为 MVP**,而**不是另起一个工程重写**。
>
> 这条同时**重述了"不创建正式工程"的准确含义**(见下方 §9 决策门该条的正文):
> 它指的是**不另起新工程**、也不在 D1 期间追求"可交付产品",
> **而不是**"原型代码将来要作废重写"。
>
> **边界**:`android/` 从此是 **MVP 的代码基座**;
> D1 的**六项交付范围不变**(设置页等 MVP 级功能**不计入** D1,见 D4「提前启动」)。

先不连接真实文件系统，完成：

- 图片列表/缩略图预览；
- 拖拽排序；
- 命名结构编辑器；
- CBZ 元数据编辑器；
- 执行计划预览；
- 冲突和警告展示。

验收标准：用户可以完整走完两个工作流，并且每个必须人工输入的字段都有明确入口。

**修复自证三层(2026-09-10 固化,凡交互/数据改动必做)**:

1. **逻辑层**:领域逻辑改动用单元测试钉死语义(如 `moveItemTo` 的"前移/拖到末尾/拖到自己格不变");

> **⚠️ 三层之外还有一层:「操作逻辑符合性」—— 2026-09-21 用户追加**
>
> 前三层回答的是「**实现是否正确**」(代码干了它该干的事),
> **没有回答「设计是否正确」**(该干的是不是这件事)。两者都绿,UI 仍可能
> **"符合规格、但不符合操作逻辑"**。故 D1 的功能测试**必须**包含这一层判断。

**4. 操作逻辑符合性走查(2026-09-21 用户追加,凡功能改动必做)**:

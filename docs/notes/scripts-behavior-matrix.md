## 3. 命名逻辑

### 3.1 `batch_rename_images.py` —— `generate_new_filename()`（L175-219）

```
[prefix + sep] + root_name + sep + <相对子路径各段用 sep 连接> + sep + <原文件名 stem> + <原扩展名>
```

- **组件拼装**（L210-217）：
  - 有前缀：`[prefix, root_name] + path_parts + [name_part]`
  - 无前缀：`[root_name] + path_parts + [name_part]`
- **占位符支持：无。** 不是模板系统，没有 `{n}`、`{title}` 之类的占位符；组件由代码固定拼接（L213-215）。
- **分隔符**：用户输入，默认 `_`（L401-403）；空输入回落 `_`。**同一分隔符同时用于组件连接（L217）和冲突检测时的「最后一段」切分（L249, L286）。**
- **子路径来源**：`subdir_path.relative_to(root_dir)` 的各段（L202-208）；`ValueError` 时退化为 `[subdir_path.name]`。
- **大小写**：**不做任何转换**，保留原样（`name_part` 与 `ext_part` 均原样取自原文件名，L198-199）。
- **空白清洗：无。** 原文件名中的空格、多空格、首尾空格一律原样保留。
- **序号补零**：**命名阶段不补零**。序号仅在冲突时才出现（见 §5）。
- **扩展名处理**：`Path(...).suffix` 只取**最后一段**扩展名，且**保留原始大小写**（L199, L217）。`a.tar.gz` → stem `a.tar` + suffix `.gz`。
- **非法字符替换：完全没有。** 全脚本 grep 无 `translate`/`maketrans`/非法字符表/`re.sub`（仅 L69 的 `re.split`）。用户输入的前缀/分隔符可含 `/`、`\`、`:`、`*` 等，直接进入文件名（L217）。
- **长度检查：完全没有。** 无 255 / 260 / MAX_PATH 相关代码。组件叠加（前缀 + 根名 + 全部子路径段 + 原名）很容易超限。

## 5. 冲突处理

### 5.1 `batch_rename_images.py` —— `ensure_unique_filename()`（L222-262）

| 情形 | 策略 | 结果示例 | 出处 |
| --- | --- | --- | --- |
| 目标不存在 | 直接用 | `前缀_根_A_001.jpg` | L240-242 |
| 最后一段是**纯数字** | **智能填补空缺序号**，位数与原数字一致 | 已有 `001`,`002` → `003`；已有 `001`,`003` → **`002`** | L256-259, L265-304 |
| 最后一段含字母 / 无分隔符 | 追加 `(1)`,`(2)`… | `hash_abc(1).jpg` | L261-262, L307-325 |

- **发现方式**：`target_path.exists()`（L241）逐文件即时检查——因为文件是边处理边落盘，后续检查能看到本次已生成的文件。
- **纯数字分支细节**（L281-302）：`num_digits = len(last_part)`；扫描 `target_dir` 中所有 `stem.startswith(f"{base_name}{separator}")` 且剩余部分 `isdigit()` 的文件，收集为 `existing_numbers`；`counter` 从 1 起找第一个空位；`str(counter).zfill(num_digits)` 后**替换最后一段**。因此 `001` 冲突可能变成 `002`，位数保持 3 位。
- **括号分支细节**（L319-325）：`f"{name_part}({counter}){ext_part}"` 循环递增直到不存在。**注意括号紧贴原名，不带分隔符**（与 `_handle_numeric_suffix` 风格不一致）。
- **大小写冲突检测：无显式检测。** 完全依赖 `Path.exists()`：Windows/macOS 默认大小写不敏感文件系统会命中，Linux 上 `A.jpg` 与 `a.jpg` 视为不同文件而**不会**触发冲突处理。
- **文件名长度上限检查：无。** 无任何长度截断或报错逻辑。
- **覆盖风险**：`ensure_unique_filename` 保证目标名唯一，因此**不会覆盖**（L240-242 的提前返回 + 两个分支都返回不存在路径）。真正的破坏性在删除策略（§8）。
- 性能：纯数字分支每次冲突都重新 `iterdir()` 全目录扫描（L288），大目录下为 O(n²)。

### 5.2 `batch_pack_cbz.py` —— 三种冲突方案（L1194-1234）

| `--conflict` | 行为 | 二次确认 | 出处 |
| --- | --- | --- | --- |
| `overwrite`（**交互默认**） | `pass`，直接覆盖。`create_cbz` 以 `"w"` 模式打开，文件被截断重写 | ❌ 无 | L1196-1197, L656 |
| `rename` | `find_available_path()` → `xxx (1).cbz`、`xxx (2).cbz`… | ❌ 无（打印 `↪`） | L1198-1200, L663-682 |
| `ask` | 逐文件询问：`1` 覆盖 / `2` 自动重命名 / `3` 手动输入文件名 / `4` 跳过（**默认跳过**） | ✅ 有 | L1201-1234 |

- **发现方式**：`cbz_path.exists()`（L1195）。
- 手动命名若已存在则循环重问（L1221-1223）；空输入 → 跳过并计入 `fail_folders`（L1227-1230）。
- 跳过/未选择覆盖 → `fail_folders.append(folder)`（L1229, L1233），但注意**这不影响后续的文件夹重命名**（§6.4）。
- **大小写冲突：无显式检测**，同 rename 脚本，依赖 `Path.exists()`（L672, L680）。
- **文件名长度上限：无检查。**
- `find_available_path()` 用 ` (i)` 格式（**带前导空格**，L679），与 rename 脚本的 `(i)`（无空格，L321）不同。
- 更新模式的冲突：`os.replace(tmp, cbz)`（L842）**无条件覆盖**，不检查 `--conflict`。

## 6. CBZ 打包逻辑

### 6.1 图片收集与过滤

- 支持的扩展名（**两脚本完全一致的 13 个**，L138-152 / L50-64）：
  `.jpg` `.jpeg` `.png` `.gif` `.bmp` `.webp` `.tiff` `.tif` `.ico` `.svg` `.heic` `.heif` `.avif`
  —— 均以 `suffix.lower()` 比较（L460, L141）。
- **只收集文件夹「直接包含」的文件，不递归**（`get_image_files()` L458-460）。
- **注意**：`.svg`、`.ico`、`.heic`、`.avif` 会被计入页数并写入 CBZ；Pillow 读不出宽高时静默退化为 `(None, None)`（`read_image_size()` L586-597，`except Exception: return None, None`），XML 中相应省略 `ImageWidth`/`ImageHeight`（L643-646）。
- 漫画文件夹识别 `find_comic_folders()`（L463-485）：`os.walk` 全树；**根目录本身若直接含图片也计入，depth=0**（L472-473）；`depth = len(folder.relative_to(root).parts)`（L480）。若父子目录都直接含图片，则**各生成一个 CBZ**。

### 6.2 写入顺序与页码重命名

`create_cbz()`（L653-660）：

```python
digits = max(3, len(str(len(images))))          # L655
with zipfile.ZipFile(str(cbz_path), "w", zipfile.ZIP_STORED) as zf:   # L656
    zf.writestr("ComicInfo.xml", xml_content)   # L657 —— 第一个条目
    for i, img in enumerate(images):
        arcname = f"{str(i + 1).zfill(digits)}{img.suffix.lower()}"   # L659
        zf.write(str(img), arcname)             # L660
```

- **页码格式**：`001.jpg`、`002.jpg`…（`zfill(digits)`，最少 3 位）。**图片数 > 999 时位数自动升为 4 位**（如 `0001.jpg`）——这会改变同批次的命名宽度，阅读器通常仍可处理。
- **扩展名被强制小写**（L659 `.lower()`），与源文件实际大小写无关。
- 条目顺序 = `images` 列表顺序 = `natural_key(f.name)` 升序（L1164-1165），**不可由用户覆盖**。
- **压缩方式：`zipfile.ZIP_STORED`（无压缩）**（L656），docstring 注明「漫画阅读器兼容性最佳」（L654）。图片本身已压缩，故不额外 deflate。
- `zf.write()` 会写入文件 mtime 作为 zip 条目时间戳；`writestr()` 用当前时间。
- 输出位置（L1183-1192）：`--out` 指定 → 该目录；否则 `depth >= 2` → `folder.parent`（series 内，与漫画文件夹同级，不嵌套）；否则 → `folder`（漫画文件夹内部）。
- `cbz_dir.mkdir(parents=True, exist_ok=True)`（L1236）——**会静默创建输出目录**。

### 6.3 ComicInfo.xml 生成 —— `build_comic_info_xml()`（L600-650）

**XML 声明与根元素（L625-627，同一行拼接）**：

```xml
<?xml version="1.0" encoding="UTF-8"?><ComicInfo xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema">
```

- 声明与根元素**之间无换行**；缩进为 4 空格（顶层）/ 8 空格（`<Page>`）。
- 编码 `UTF-8`；`writestr` 传入 `str` 时 zipfile 自动按 UTF-8 编码。
- 元素顺序严格遵循 ComicInfo 标准 `xs:sequence`（docstring L611-618 引用 `anansi-project/comicinfo` v2.0 `ComicInfo.xsd`）：`Title → Series → Volume → Writer → PageCount → LanguageISO → Pages`。

**字段清单与取值来源**：

| 顺序 | 元素 | 是否总生成 | 取值来源 | 出处 |
| --- | --- | --- | --- | --- |
| 1 | `<Title>` | ✅ 总是 | `derive_metadata()` 的 `title`（已清洗、已剥卷号） | L628 |
| 2 | `<Series>` | ✅ 总是 | `depth<=1` 时 = title；`depth>=2` 时 = 外层文件夹名清洗结果 | L629, L569-576 |
| 3 | `<Volume>` | ⚠️ 仅 `volume is not None` | `detect_volume()` / `infer_volumes()` / 用户输入。**实际到达 XML 的恒为 `int`**：`auto` 模式下小数卷必然触发 `renumber_series_volumes()` 被 `ceil` 为整数（L448-451）；`input` 模式只接受 `isdigit()`（L304）；`skip` 模式恒为 `None`。`resolve_volume` 的返回类型标注含 `float`（L282），但无路径可送达此处 | L631-632, L282-304, L448-451 |
| 4 | `<Writer>` | ⚠️ 仅非空字符串 | 文件夹名开头 `[]` 内容（`depth>=2` 时取**外层**） | L633-634 |
| 5 | `<PageCount>` | ✅ 总是 | `len(image_infos)` | L637 |
| 6 | `<LanguageISO>` | ⚠️ 仅 `language_iso` 为真值 | `--lang ja/zh` 或逐文件夹选择 | L638-639 |
| 7 | `<Pages>` + `<Page>` | ✅ 总是（可为空） | 每张图一条，顺序即页码顺序 | L640-648 |

**`<Page>` 属性（L641-647）**：

```
Image="{index}" Type="Story" ImageSize="{size}" [ImageWidth="{w}"] [ImageHeight="{h}"]
```

- `Image` 从 `0` 开始（`enumerate` 默认），**与 zip 内文件名 `001.jpg` 相差 1**（ComicInfo 标准约定如此）。
- `Type="Story"` 固定；`DoublePage` / `Key` / `Bookmark` 省略（docstring L616-618）。
- `ImageSize` 总是生成：打包模式取 `img.stat().st_size`（L1170）；更新模式取 `len(zf.read(n))`（L824）。
- `ImageWidth` / `ImageHeight` 仅在 Pillow 成功读出时生成（L643-646）；Pillow 缺失时**整个脚本拒绝运行**（L933-939）。

**转义**：`Title` / `Series` / `Writer` / `LanguageISO` 经 `xml.sax.saxutils.escape`（L126 导入，L628-639 使用）——只转义 `&`、`<`、`>`，**不转义引号**（文本节点无需）。

**language 处理汇总**：

| 模式 | 结果 | 出处 |
| --- | --- | --- |
| `skip`（交互默认 / `--lang skip`） | **不生成** `<LanguageISO>` | L215-217, L257-258 |
| `--lang ja` | 全部固定 `ja` | L206-208 |
| `--lang zh` | 全部固定 `zh` | L209-211 |
| `--lang interactive`（无现状） | 逐文件夹：`1` 跳过 / `2` ja / `3` zh | L270-273 |
| `--lang interactive`（更新模式且有现状） | 额外提供 `4` **置空（去掉）** → 返回 `None` → 不生成标签；`1` = 保留现状 | L259-269 |

### 6.4 打包后的文件夹重命名（L1261-1284）

- 候选集：对 `comics` 中每个 `depth != 0` 的项，取 `folder`（`depth<=1`）或 `folder.parent`（`depth>=2`），去重（L1265-1270）。
- 新名 = `clean_folder_name(cand.name)`（**保留** `[作者]` 与 `（）` 原作，去开头 `()` 前缀与尾部 `[]`）；相同则跳过（L1272-1274）。
- 目标已存在 → 打印警告并跳过（L1276-1278）。
- 成功 → `cand.rename(new_path)` 并记入 `rename_map`（L1280-1282）。
- **若外层 series 被重命名，回填 `success_folders` 路径**（L1286-1295），供后续删除使用。
- ⚠️ **该重命名在打包循环之后无条件执行**（L1261 起），**不区分打包成功/失败**，也不在确认提示或 `--dry-run` 预览中体现。

## 10. 两脚本的行为差异与共同点

### 共同点

1. **图片扩展名集合完全相同**（13 个，含 `.svg`/`.ico`/`.heic`/`.avif` 等非常规漫画格式），且都按 `suffix.lower()` 比较（rename L50-64；cbz L138-152）。
2. **都只处理「直接包含」的图片**，不做递归收集（rename 按子目录逐层处理；cbz 的 `get_image_files` 非递归）。
3. **都用 `re.split(r"(\d+)", ...)` 做自然排序**，字母段小写比较（L67-69 / L155-170）。
4. **`root` 都缺省为脚本所在目录**，都会静默作用于该目录（L339 / L955-968）。
5. **都没有非法字符清洗、没有文件名长度上限检查**（全文 grep 无 `translate`/`maketrans`/`255`/`260`/`MAX_PATH`/截断逻辑）。
6. **都没有撤销/回滚**；`KeyboardInterrupt` 只打印提示，已完成的操作不可逆。
7. **大小写冲突都不显式检测**，仅靠 `Path.exists()`（依赖文件系统语义）。
8. **都是「扫描 → 打印 → 一次确认 → 执行」的单次流程**，无持久化计划、无中间状态。
9. **都在结束处 `wait_for_exit()`**，且都重定向/兼容 `EOFError`（L114-122 / L853-858）。
10. **都通过 PEP 723 内联元数据声明 `requires-python = ">=3.10"`**（rename L2-4；cbz L2-7，cbz 额外依赖 `Pillow`）。

### 差异

| 维度 | `batch_rename_images.py` | `batch_pack_cbz.py` |
| --- | --- | --- |
| CLI 框架 | 裸 `sys.argv`，1 参数 | `argparse`，10 参数，带 help/epilog |
| 依赖 | 纯标准库 | Pillow（缺失即拒绝运行，L933-939） |
| 自然排序键 | 混合类型列表，保留空串（L67-69） | `(类型, 值)` 元组，跳过空串（L155-170） |
| 排序可配置性 | 8 种可选（名称/时间/大小 × 升降） | 图片顺序**固定**升序；仅 `--volume auto` 有多级排序 |
| dry-run | ❌ 无 | ✅ `--dry-run`（但更新模式绕过） |
| 预览完整度 | 固定 5 条 | 全量列表（按系列分组、列对齐） |
| 命名能力 | 前缀 + 根名 + 子路径 + 原名，自定义分隔符 | 仅清洗（去括号/尾部标注），无前缀/模板概念 |
| 冲突策略 | 自动（智能补数字 / `(n)`），无用户选择 | 三选一（`overwrite` 默认 / `rename` / `ask`） |
| 冲突后缀格式 | `(1)` 紧贴原名（L321） | ` (1)` 带前导空格（L679） |
| 破坏性默认 | 移动 + **force rmtree** | **overwrite** + 可选 `-d` 删除 |
| 危险操作确认 | 1 次总确认，删除无独立确认 | 1 次总确认；覆盖无独立确认；`-u` 零确认 |
| 就地改写 | 移动源文件（L509） | `os.replace` 重写 CBZ（L842） |
| 元数据 | 无 | ComicInfo.xml（Title/Series/Volume/Writer/PageCount/LanguageISO/Pages） |
| 压缩 | — | `ZIP_STORED` 无压缩（L656）；更新时保留原压缩类型（L841） |
| 结束行为 | 打印统计 | 打印统计 + **额外重命名文件夹**（L1261-1284） |

**联动关系（两脚本 docstring 均声明）**：先 `batch_rename_images.py` 保证排序与命名一致，再 `batch_pack_cbz.py` 打包（rename L36-40；cbz L55-59）。rename 的 docstring 明确警告：**移动模式会把图片扁平化到根目录**，如需按文件夹打包 CBZ 必须用复制模式（L39-40）——这正是 GUI 需要消解的耦合。

### 11.3 建议 GUI 侧的最小安全基线（对照 §2 产品约束）

1. **扫描 / 决策 / 执行彻底分离**：把 `find_comic_folders` / `scan_subdirectories` 的扫描结果作为持久化计划对象，所有破坏性选项（移动、删除、覆盖、重命名）都在执行前确定并纳入同一份预览。
2. **破坏性默认全部关闭**：源文件默认保留；冲突默认「不覆盖」（自动重命名或跳过）；删除独立开关 + 独立确认 + 完整影响清单（递归）。
3. **一切自动推断可见可改**：卷号（`*` 推断 / `?` 待定）、语言、页序、CBZ 文件名、冲突改名结果，全部在预览中可编辑，符合「建议 ≠ 事实」。
4. **dry-run 语义统一**：一个开关覆盖打包 / 更新 / 重命名 / 删除全部阶段，输出结构化计划而非纯文本。
